1. Point de départ et architecture cible

Ce qui existe déjà : une plateforme de réservation complète (7 microservices FastAPI, gateway, Next.js + admin Vite, Stripe, i18n fr/en/ar). Le catalogue contient activités (prix, durée, localisation, latitude/longitude, catégorie), créneaux, hébergements, vols, voitures et transferts.

Ce qui manque pour la présentation : aucune brique IA n'existe encore ; pas de restaurants, plages, monuments ni météo ; pas d'attributs comme « effort de marche » ou « public famille » sur les activités.

Principe directeur : le LLM comprend et explique ; les faits viennent de la base, le classement d'un score mesurable et le planning d'un solveur d'optimisation. C'est ce qui rend l'itinéraire fiable, explicable et évaluable — et c'est la réponse d'un data scientist à la question « comment éviter les hallucinations ? ».

(X-Internal-Api-Key, appels HTTP synchrones) | v Claude API (démo) | Ollama local (secours) OpenStreetMap Overpass · Open-Meteo

Pourquoi un nouveau microservice ai ?

  • Isolation : le moteur peut être lent ou en panne sans bloquer la réservation et le paiement.
  • Database-per-service respecté : vecteurs, POI, conversations et journaux LLM vivent dans voyara_ai ; les données métier sont lues via /internal/*, jamais par jointure SQL.
  • pgvector plutôt qu'une base vectorielle externe : une seule technologie de base à opérer, largement suffisante pour quelques milliers de documents.
  • LLM hybride : Claude pour la qualité en démo, Ollama local pour le coût nul, le hors-ligne et la comparaison scientifique.

2. Comment utiliser ce guide avec Claude Code

Le cycle d'une étape

  1. Ouvre Claude Code dans le dossier Voyara, sur une branche dédiée (ex. ia/etape-04).
  2. Active le plan mode, colle le prompt de l'étape tel quel.
  3. Lis le plan proposé ; corrige-le si besoin ; valide.
  4. Laisse Claude Code coder, lancer les tests et écrire le rapport.
  5. Lis le rapport dans docs/ia/rapports/, vérifie toi-même la section 7 « Ce que je dois vérifier ».
  6. Commit, puis ouvre une nouvelle session pour l'étape suivante (contexte propre ; les rapports font le lien).

Structure commune de chaque prompt

  • En-tête de contexte (gris) : fichiers à lire, plan mode, contraintes permanentes du projet.
  • Corps (noir) : ce qu'il faut construire, précisément.
  • Rapport obligatoire (terracotta) : ce que Claude Code a fait, pourquoi, quelles alternatives il a écartées, comment il a vérifié.

Module 1 — Comprendre le voyageur (NLU)

Module 1 — Compréhension du besoinDurée indicative : 2–3 jours

Objectif

Transformer « Je vais à Djerba 3 jours, 300 DT, en famille, culture et plage » en une demande structurée et validée.

Pourquoi ce choix (regard d'expert)

C'est de l'extraction d'information : on impose au LLM un schéma (sortie structurée / tool use) au lieu de parser du texte libre, ce qui supprime la majorité des erreurs de format. Annexe A — Glossaire IA

TermeDéfinition
LLMGrand modèle de langage (Claude, Qwen…) ; ici utilisé pour comprendre et expliquer, pas pour calculer.
Sortie structurée / tool useLe LLM remplit un schéma JSON ou appelle une fonction au lieu d'écrire du texte libre.
EmbeddingVecteur numérique représentant le sens d'un texte ; deux textes proches ont des vecteurs proches.
pgvectorExtension PostgreSQL pour stocker des vecteurs et chercher les plus proches (index HNSW).
BM25Score de recherche lexicale classique, fort sur les noms propres et mots exacts.
RRFReciprocal Rank Fusion : fusion de plusieurs classements par la somme de 1/(k + rang).
RAGRetrieval-Augmented Generation : le LLM répond à partir de documents récupérés dans nos données.
MMRMaximal Marginal Relevance : re-classement qui équilibre pertinence et diversité.
Démarrage à froidAbsence d'historique pour un nouvel utilisateur ou une nouvelle activité.
CP-SATSolveur de programmation par contraintes d'OR-Tools (Google) pour les problèmes combinatoires.
AgentBoucle où le LLM choisit des outils, observe le résultat et décide de l'étape suivante.
LLM-as-judgeÉvaluation d'une sortie par un LLM selon une grille ; à recouper avec des humains.
Recall@k / nDCGMétriques de recherche : part des documents pertinents trouvés dans le top k / qualité de l'ordre.
F1Moyenne harmonique de la précision et du rappel, utilisée pour l'extraction de champs.
